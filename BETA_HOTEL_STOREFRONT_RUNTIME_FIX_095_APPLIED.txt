iumrah Beta — Hotel Storefront runtime fix 095
Date: 2026-09-06
Source state: beta-iumrah-app-main 13.zip + Hotel Storefront v1 + buildfix v2

Fixes:
- Hotel catalogue loading is independent from the storefront flight-price request. One failed request can no longer blank the entire Hotels tab.
- Hotels are never filtered out just because the package quote is still being prepared.
- Package quotes now use the fresh price from HotelDetail as a fallback when the list payload does not expose the fresh 48h price.
- Quotes are rebuilt after hotel details arrive; the previous implementation loaded details but did not recalculate prices afterwards.
- Hotel detail refresh feeds its latest price back into HotelStorefrontStore immediately.
- The app still starts Hotel Storefront preparation from RootView at launch; the Hotels tab consumes the warmed catalogue/cache.
- Storefront flight request has a bounded 10-second timeout and no longer prevents hotel rendering.
- Local Centrum Air logo asset is used for IATA C6 instead of the unreliable remote carrier logo.
- Storefront disk snapshot version advanced to v3 so the corrected data path starts clean while the separate persistent photo cache remains reusable.

Important:
The package price still requires the Package Engine endpoint /api/package/storefront/flights introduced by Hotel Storefront v1. If Deploy iumrah Package Engine was not run after v1, run it once before validating package prices in TestFlight.
