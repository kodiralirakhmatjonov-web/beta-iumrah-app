iumrah Beta — Package Builder direct + flexible architecture 099
Date: 2026-09-07

Scope: package-generation flow only. Existing Weekend Umrah behavior is intentionally preserved.

Changed:
- Trip Builder opens with the new “Build your Umrah” positioning and personal-package marketing copy in all four client languages.
- Published Direct is the primary package path: the pilgrim chooses a staff-published direct flight product first; supplier airfare stays out of the customer UI.
- Published recommendations are route-scoped from the selected origin and support both complete round-trip products and separately published outbound/return products.
- If only one published product shape exists for a route, the flight list automatically opens the populated presentation instead of an empty tab.
- Flexible Dates opens the calendar. Green days are derived only from published direct-flight inventory in D1.
- Selecting dates without a published direct pair shows an inline yellow warning and a second confirmation explaining 1–2 stops / potentially higher fare and package total.
- The warning offers exactly two paths: return to direct-flight dates or continue with flexible dates.
- Flexible Dates preserves the existing hotel -> Ignav outbound -> compatible return -> final package flow.
- Published Direct uses a new D1-only resolver after hotel selection, converts the selected published itinerary into the existing verified FlightOffer contract, and calculates the final package with the existing LocalPackagePricingEngine.
- Published Direct does not launch a new Ignav search after hotel selection.
- Public published-flight discovery capacity was raised to 300 rows so the six-month direct-flight calendar is less likely to omit later published dates.

Ignav/cache behavior verified:
- Exact provider searches are cached in D1 for 12 hours.
- A cache hit does not issue a second Ignav upstream request.
- The published-direct resolver is D1-only and does not call the flight provider.

Not changed:
- Weekend Umrah product logic
- Existing package pricing formula / markup mathematics
- Existing hotel recommendation and hotel-price architecture
- Existing flexible-date Ignav search implementation
- Existing booking/payment architecture

- All Sources Swift files: swiftc frontend syntax parse PASS

- Package Engine contract tests: 31/31 PASS
- Package Engine runtime tests: 18/18 PASS, including D1-only published-direct resolver coverage
- Full Xcode simulator/TestFlight build is not available on Linux and should run in the existing macOS GitHub workflow.
